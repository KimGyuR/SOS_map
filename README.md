# 동네SOS (Expo 데모)

주변 생활 민원을 지도에서 확인하고, 사진과 위치를 첨부해 등록하는 React Native 앱입니다. 지역 축제별 불편 신고도 같은 민원 목록과 연결됩니다.

목록에서는 지역별로 민원을 필터링하고 좋아요를 누르거나 상세 내용을 볼 수 있습니다. 신고 등록은 사진·내용 작성 다음에 개인정보 블러 점검, AI 처리 미리보기 순서로 진행됩니다.

## 실행

```bash
npm install
npx expo start
```

현재 위치·카메라 기능을 확인하려면 실제 기기 또는 Expo 개발 빌드에서 실행하고 권한을 허용하세요. Expo Go에서는 Android 지도 키 없이도 확인할 수 있습니다. 웹에서는 네이티브 지도 모듈 대신 민원 핀을 누를 수 있는 지도 미리보기 화면을 표시합니다. 독립 Android 앱을 빌드할 때는 Google Maps Android SDK 키를 설정해야 합니다.

PowerShell에서 키를 설정한 뒤 앱을 실행할 수 있습니다.

```powershell
$env:GOOGLE_MAPS_API_KEY="YOUR_RESTRICTED_ANDROID_MAPS_KEY"
npx expo start
```

독립 Android 앱에서 키를 설정하지 않으면 지도 타일이 표시되지 않을 수 있습니다. iOS에서는 Apple 지도를 사용합니다.

## 데모 범위와 운영 전 필요한 연동

- 아이디, 이름, 이메일, 비밀번호, 비밀번호 확인으로 기기 내 계정을 만들고 같은 아이디·비밀번호로 로그인할 수 있습니다. 로그인 상태도 기기에 저장되어 앱을 다시 열면 유지되며, 로그아웃하면 저장된 로그인 상태만 해제됩니다.
- 계정 데이터는 기기/브라우저의 AsyncStorage에 저장됩니다. 비밀번호 원문 대신 계정별 무작위 salt와 PBKDF2-SHA-256 해시를 저장하지만, AsyncStorage 자체는 암호화되지 않으며 계정은 다른 기기와 동기화되지 않습니다. 이 로그인은 데모용 로컬 인증이며 실제 서비스 인증을 대체하지 않습니다.
- 민원, 축제, 좋아요, AI 처리 예상은 샘플 데이터와 로컬 상태로 동작합니다. 앱을 새로 실행하면 데모 변경 내용은 초기화되며 등록 내용은 서버나 행정기관으로 전송되지 않습니다.
- AI 분류·처리 예측은 예시 문구이며 실제 AI 모델과 연결되어 있지 않습니다.
- 얼굴 자동 감지·블러 모델은 연결되어 있지 않습니다. 등록 전 사진 점검 화면에서 사용자가 얼굴·번호판 등 식별 정보와 직접 블러 적용 여부를 확인합니다. 이 확인은 이미지 픽셀을 검사하지 않으므로, 실제 배포 전에는 업로드 전에 얼굴을 감지하고 블러를 적용하는 검증된 처리 파이프라인을 연결해야 합니다.
- 동물 사체 사진은 자동 블러 처리하지 않습니다. 앱은 등록 확인을 차단하고 직접 편집한 사진인지 확인하도록 안내합니다.
- 사진은 선택 후 화면에만 표시되며 원격 서버로 업로드되지 않습니다.

실서비스에서는 서버 측 사용자 인증과 비밀번호 저장, 이메일 검증·비밀번호 재설정, 민원 API, 지도 키 제한, AI 이미지 처리 및 개인정보 보관 정책을 별도로 구성해야 합니다.

## 대구 색상과 지도

- `src/theme/colors.ts`: 대구 으뜸색에서 착안한 화면용 팔레트입니다. 공식 RGB 지정값이 아닌 디자인 조정값입니다. 목련 은미색 배경, 달구벌 진녹색 본문, 대구하늘 청색 강조를 중심으로 사용합니다.
- `src/components/AppIcon.tsx`: 카테고리, 지도 핀, 메뉴에 공통으로 사용하는 24px SVG 선형 아이콘입니다.
- 웹 지도는 OpenStreetMap 타일을 사용합니다. 운영 시 트래픽에 맞는 타일 공급자를 선택하고 `EXPO_PUBLIC_MAP_TILE_URL`과 `EXPO_PUBLIC_MAP_ATTRIBUTION`을 함께 설정할 수 있습니다. 기본 공급자의 정책: https://operations.osmfoundation.org/policies/tiles/
- 샘플 민원은 원래 좌표에 남습니다. 현재 위치로 이동해도 샘플 좌표를 바꾸지 않으며 지도 범위에 포함된 민원만 주변 목록에 표시합니다.
- 웹에서는 주소 역변환을 제공하지 않습니다. GPS 좌표는 등록에 사용되며, 주소는 직접 입력합니다. 위치 거부·시간 초과 시 재조회할 수 있습니다.
- Android 독립 빌드는 `GOOGLE_MAPS_API_KEY`를 설정하고 개발 빌드를 새로 만들어야 합니다. iOS는 Apple 지도를 사용합니다.

## 코드 구조와 검증

- `src/app/`: Expo Router 진입점. 기존 `?screen=map|list|festival|mypage` 주소를 유지합니다.
- `src/SosApp.tsx`: 로그인 상태에 따른 화면 조합과 공통 레이아웃.
- `src/screens/`: 로그인, 지도, 목록, 축제, 프로필, 상세 모달, 신고 작성 UI.
- `src/hooks/`: 인증 세션, 민원 상태, 위치 조회, 신고 작성 로직. `useAppModel`은 기능 간 연결만 담당합니다.
- `src/domain/`: 데이터 타입, 샘플 데이터/카테고리, 입력 검증, 민원 reducer와 지도 범위 계산. UI 없이 테스트할 수 있습니다.
- `src/components/`: 공통 버튼, 민원 카드, 메뉴, 플랫폼별 지도, 아이콘.
- `src/lib/`: 계정 저장, GPS/주소 조회, 웹 지도 카메라 동기화.
- `src/theme/`: 대구 팔레트와 공통 화면 스타일.

로그인 정보의 기존 저장 키와 형식은 유지합니다. 민원과 좋아요는 앱 실행 중 메모리에만 보관하며, 상세 화면은 선택한 민원 ID로 원본 데이터를 조회합니다. 지도 이동이나 신고 폼 입력만으로 전체 지도 마커를 다시 만들지 않도록 마커 데이터를 메모화했습니다.

```bash
npm run check       # lint + typecheck + 회귀 테스트
npm test            # Node 내장 테스트 러너, 별도 테스트 패키지 없음
npx expo export --platform all
```

회귀 테스트는 좋아요/선택 상태, 중복 등록, 지도 범위, 회원가입·신고 검증, 지도 확대 수준 유지, 웹 SVG 접근성 속성, 위치 권한과 주소 조회 실패 처리를 확인합니다. 장치 API는 모의 구현을 사용하므로 실제 기기의 GPS·카메라·지도 제스처 확인은 별도로 필요합니다.
